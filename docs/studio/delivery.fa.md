# تحویل مستقیم سفارش

فایل‌های درخواستی در همان محیطی که کاربر سفارش داده تحویل داده شوند. پیش‌فرض، تحویل مستقیم خود خروجی است؛ عکس تکی، چند عکس، متن و پرامپت به ZIP یا بستهٔ کامل پروژه نیاز ندارند. فایل سفارش به Git برگردانده نمی‌شود و تحویل به حساب GitHub، commit، push یا PR نیاز ندارد. تغییر و انتشار خود کیت، کار جداگانهٔ نگه‌داری ریپو است.

- فایل‌های خروجی واقعی را با نام روشن در پاسخ نهایی پیوست کن یا لینک قابل بازکردن/دانلود همان محیط را بده. در محیط محلی، لینک فایل روی دیسک و در محیط دارای پیوست، فایل قابل دانلود ارائه شود؛ مسیر داخلی محیط ابری به‌تنهایی لینک دانلود نیست.
- برای عکس تکی یا چند عکس، فایل‌های تصویر را جدا و مرتب ارائه کن. متن یا پرامپت را مستقیم در پاسخ یا به‌صورت فایل متنی قابل استفاده بده؛ همراهان ضروری مثل مراجع پرامپت را نیز جدا تحویل بده. تعداد چند فایل به‌تنهایی دلیل ساخت ZIP نیست.
- فقط وقتی کاربر بستهٔ پروژه می‌خواهد یا انتقال و ادامهٔ پروژه به مجموعهٔ منابع و تنظیمات نیاز دارد، `npm run content -- pack <id>` را اجرا کن و ZIP اعلام‌شده را تحویل بده. بسته شامل تنظیمات، ورودی‌ها، منابع، تاریخچه و خروجی‌های همان سفارش است. لازم نیست کل کیت یا dependencyها دوباره بسته‌بندی شوند.
- سفارش اصلی و `REVIEW.md` در `.local/projects/<id>` حفظ شوند؛ تحویل گزارش داخلی یا همهٔ منابع به کاربر برای هر خروجی ساده اجباری نیست.
- پیش از ارسال، وجود و بازشدن فایل‌ها، محتوای ZIP و درست‌بودن مقصد لینک‌ها را بررسی کن. وضعیت بازبینی و محدودیت‌های واقعی را کوتاه بگو؛ فایل ساخته‌نشده یا خروجی بررسی‌نشده را آماده معرفی نکن.

اگر محیط پیوست یا دانلود فایل را پشتیبانی نمی‌کند، این محدودیت و مسیر فایل موجود را صریح بگو و راه انتقال قابل اجرای همان محیط را ارائه کن. Git جایگزین خودکار تحویل نیست. ZIP سفارش و ورودی‌های مشتری خصوصی‌اند و وارد ریپوی عمومی، release یا PR نمی‌شوند.

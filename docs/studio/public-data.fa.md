# دادهٔ روز در سفارش

این ابزار فقط دادهٔ لازم برای تولید محتوای همان سفارش را می‌گیرد: تقویم، آب‌وهوا، اوقات شرعی، مسابقه و بازار. کشف خبر مسیر مستقل [خبریاب کلام](news-discovery.fa.md) است؛ این ابزار RSS یا پایش رسانه اجرا نمی‌کند. هیچ API مدل، کلید شخصی یا اشتراک ارائه‌دهنده لازم نیست؛ درخواست‌های HTTPS به منابع عمومی انجام می‌شود.

## رفتار عامل

برای قالب‌های صبح‌بخیر محلی، صبح‌بخیر کلام، بازار و ورزش، سفارش تازه `dataRequests` مناسب دارد. `content brief <id>` اگر مدرک تازه نداشته باشد دریافت داده را اجرا می‌کند. تاریخ امروز از ساعت سیستم و منطقهٔ `Asia/Tehran` گرفته می‌شود؛ تاریخ UTC یا حافظهٔ مدل مبنا نیست. شهر و رقابت از همان تنظیمات فرم سفارش خوانده می‌شوند. برای ورزش، رقابت، حالت نتیجه/لیگ/پیش‌رو و تاریخ لازم را از درخواست بگیر؛ رقابت نامشخص را حدس نزن.

با `content refresh <id>` دریافت را جدا اجرا و گزارش را بخوان. `--force` مدرک قبلی را دوباره از منبع می‌گیرد؛ `--replace` صریحاً اجازهٔ جایگزینی فیلدهای دستی همان داده‌هاست. در حالت عادی فیلدهای غیرخالی ادمین حفظ می‌شوند و فقط مقدارهای خالی یا مقدارهایی که هنوز متعلق به دریافت قبلی‌اند به‌روز می‌شوند. fieldهای حفظ‌شده در گزارش `preserved` مشخص‌اند؛ نباید آن‌ها را «دریافت‌شده از منبع» معرفی کرد.

دادهٔ هر اسلاید مقصد مستقل دارد. فایل‌های مدرک زیر `analysis/data/` همان سفارش‌اند: مقدار، منبع و URL، زمان دریافت، تاریخ معتبر، منطقهٔ زمانی، وضعیت و hash. مدرک منقضی یا دست‌کاری‌شده پیش از brief و هنگام export رد می‌شود. تغییر روز تهران، تغییر شهر یا رقابت، مدرک قبلی را معتبر نگه نمی‌دارد. مقادیر قبلی و خروجی‌ها در history باقی می‌مانند.

## منابع و معنای داده

| داده | منبع و کنترل |
| --- | --- |
| تاریخ و هفته | تبدیل شمسیِ اصلی Studio با زمان تهران؛ هفته از شنبه تا جمعه؛ ماه و سال واقعی |
| قمری و شش وقت شرعی | AlAdhan با مختصات گلبهار/چناران و روش شیعهٔ اثناعشری؛ تاریخ، مختصات و timezone پاسخ کنترل می‌شوند؛ قمری محاسباتی جای تقویم رسمی مناسبت‌ها نیست |
| آب‌وهوا | Open-Meteo؛ وضعیت و زمان مشاهده، حداقل/حداکثر، باد، رطوبت و پوشش پیشنهادی؛ برای روز آینده «پیش‌بینی» است و با وضعیت فعلی مخلوط نمی‌شود |
| مناسبت و تعطیلی | صفحهٔ ماهانهٔ Bahesab به‌عنوان بازنشر تقویم، پشتیبان PNLdev و دادهٔ جهانی CC0 Persian Calendar؛ منبع پشتیبان به نام منبع رسمی معرفی نشود |
| ورزش | فهرست رقابت‌های Studio و TheSportsDB؛ شناسهٔ لیگ/فصل و روز کنترل، ساعت UTC به تهران تبدیل؛ مسابقهٔ لغوشده یا نتیجهٔ درحال‌بازی نتیجهٔ نهایی معرفی نشود |
| بازار | Baha24؛ در خطا صفحهٔ عمومی TGJU؛ ریال TGJU برای چهار نرخ ایرانی به **تومان قرارداد Studio** تبدیل، بیت‌کوین به دلار باقی می‌ماند |

در بازار، درصد روی وب لزوماً تغییر ۲۴ساعته نیست. تغییر ۲۴ساعته فقط با سابقهٔ واقعی ۱۸ تا ۳۰ ساعت همان منبع و همان واحد محاسبه می‌شود؛ بدون سابقه، خالی می‌ماند و صفر نوشته نمی‌شود. اگر فقط ساعت یک نرخ معلوم باشد، تاریخ آن از روی حدس به امروز نسبت داده نمی‌شود و وضعیت `needs-review` است. نرخ قدیمی یا ساعت نامعلوم مسابقه با نمونهٔ ساختگی جایگزین نشود.

## نبود منبع مستقیم و استفاده از ابزار وب محیط

`blocked` و `needs-review` را به ادمین روشن بگو، ولی ابتدا ابزار وب همین محیط را بررسی کن. عامل می‌تواند از سایت عمومی معتبر برای **همان داده، تاریخ، شهر و رقابت** استفاده کند. این کار جستجوگر خبر نیست. مقدار، تاریخ واقعی مشاهده و متن شاهد از صفحه خوانده شود؛ عنوان یک نتیجهٔ جست‌وجو به‌تنهایی کافی نیست. اگر ابزار وب هم نیست یا سند معتبر پیدا نشد، فقط بخش وابسته منتظر دادهٔ تأییدشدهٔ ادمین بماند.

برای ثبت مدرک فایل JSON بساز و سپس اجرا کن:

```bash
npm run content -- data-import my-job --binding rates-request --file /path/evidence.json
```

فایل شامل `task`، `reviewed: true` فقط پس از بازبینی واقعی، `reviewNote`، `values` با نام فیلدهای کاتالوگ، و `meta` است. در meta، `date` به شکل YYYY-MM-DD، `timeZone: Asia/Tehran` و شهر مرتبط لازم است؛ آب‌وهوا/بازار `observedAt` کامل با offset زمانی می‌خواهند. در ورزش `competitionId` و `mode` باید مطابق انتخاب باشند؛ تقویم `todayIndex`، `holidayIndexes` و `holidaysComplete` لازم دارد. `sources` آرایه‌ای از `url`، `retrievedAt` و `excerpt` واقعی است. زمان دریافت با زمان وقوع مسابقه یا زمان آخرین نرخ یکی نیست.

در نرخ‌ها `meta.units` برای هر پنج فیلد الزامی است: چهار نرخ ایرانی `IRR` یا `toman`، بیت‌کوین `USD`. ابزار واحدها را به قرارداد اصلی تبدیل می‌کند. فایل نمونه در `examples/public-data/web-evidence.example.json` است؛ placeholderها مدرک نیستند. پس از import، brief دوباره بساز؛ دادهٔ وب تازه و تأییدشده بی‌دلیل با مسیر مستقیمِ خراب جایگزین نمی‌شود.

برای اطلاعات دستیِ قطعی، اتصال همان درخواست را با `enabled: false` خاموش کن و دادهٔ ادمین و منبعش را ثبت کن. این انتخاب به معنی تأیید خودکار تازگی داده نیست. `required: false` فقط برای ویجت اختیاری مجاز است که حذف یا نبودش روشن شده باشد؛ برای دورزدن خطا روی دادهٔ ضروری استفاده نشود.

## فرمان‌های نگه‌دارنده

```bash
npm run data -- catalog
npm run data -- fetch weather --city chenaran
npm run data -- fetch sports --competition premier_league --mode upcoming --date 2026-11-04
npm run content -- data-plan my-job
npm run content -- refresh my-job
```

در متن/موشن هم می‌توان نتیجهٔ دریافت را با مقصد `context` در سفارش ثبت کرد تا عامل از دادهٔ مستند استفاده کند. دادهٔ شخصی سفارش به سرویس‌های داده فرستاده نمی‌شود؛ درخواست عمومی فقط مختصات شهر، روز یا شناسهٔ لیگ را دارد.
